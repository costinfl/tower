# Product Boundaries

## Target Users

Primary users:

- Developers
- Technical Leads
- Software Architects

Secondary users:

- QA Engineers
- DevOps Engineers
- Release Managers

Tower supports these roles without replacing their existing responsibilities.

---

# Ownership

Tower owns:

- Release Packs
- Promotion Paths
- Developer handover information
- Environment observations
- Generated documentation

Tower does not own:

- Source code
- Pipelines
- Kubernetes resources
- Work items
- Deployment execution

---

# Core Questions

Tower must always answer:

- What application version is deployed in each environment?
- Which applications belong to a Release Pack?
- Which promotion path is the Release Pack following?
- What information must be handed over before deployment?

---

# External Systems

Tower consumes information from engineering tools.

These systems remain authoritative for their own domains.

Tower provides a consolidated operational view.
